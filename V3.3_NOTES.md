# v3.3 — Explicit direction metadata integration

New: `backend/direction_metadata.py` and `backend/test_direction_metadata.py`.

`GET /api/v1/heatmap/events?team_id=1&normalize=true` and
`GET /api/v1/heatmap/compare?team_a=1&team_b=2&normalize=true`
require `FOOTBALLIQ_DIRECTION_METADATA` and `FOOTBALLIQ_HISTORICAL_EVENTS`.

Example metadata (replace all placeholder values with independently reviewed facts):

```json
{
  "verification_status": "manually_verified",
  "evidence_note": "Describe the independent source and review method",
  "source_sha256": "<SHA-256 of exact event JSON bytes>",
  "teams": {
    "1": {"1": "left_to_right", "2": "right_to_left"},
    "2": {"1": "right_to_left", "2": "left_to_right"}
  }
}
```

No automatic inference from event positions. The `manually_verified` field is an attestation supplied by the data curator; software validates presence, structure and source binding, not the truth of that attestation. The actual match still needs independent video/metadata validation. Default `normalize=false` preserves raw positions. Backend: 60 pytest tests passed. React build and real-match validation remain pending.
